### 📊 Metrics Collection Summary

This project establishes a **comprehensive metrics collection framework** for the **Kinesis → Lambda → BigQuery** data pipeline using **k6**. The goal is to achieve full visibility into system performance, reliability, and scalability across all integrated services.

---

## Collected Metrics

### Kinesis Metrics
Automatically collected through k6's built-in HTTP monitoring, capturing:
- **Request Duration**: Time taken for each PutRecord API call
- **Throughput**: Number of requests per second
- **Success Rate**: Percentage of successful vs failed requests
- **Error Count**: Total number of failed PutRecord operations
- **Data Transfer Volume**: Amount of data sent to Kinesis stream

### Network Metrics
Continuously tracked for every request, including:
- **DNS Lookup Time**: Time to resolve domain names
- **TCP Connection Time**: Time to establish TCP connection
- **TLS Handshake Duration**: Time for SSL/TLS negotiation
- **Total Request Latency**: End-to-end time including all network phases

### Lambda Metrics
Retrieved periodically via the **AWS CloudWatch API**, providing insights into:
- **Invocation Counts**: Total number of Lambda function executions
- **Execution Durations**: Time taken for each Lambda execution (avg, p95, max)
- **Error Occurrences**: Number of failed Lambda invocations
- **Throttles**: Number of throttled invocations due to concurrency limits
- **Concurrent Executions**: Number of concurrent Lambda instances running

AWS **SigV4 authentication** ensures secure API access.

### BigQuery Metrics (Planned)
Future integration will use the BigQuery REST API to measure:
- **Query Execution Time**: Duration of BigQuery insert operations
- **Data Processed**: Amount of data written to BigQuery tables
- **Insert Error Rates**: Failed insert operations

---

## Collection Methods

**Kinesis**: k6's built-in HTTP metrics automatically track all PutRecord API calls with no additional configuration required.

**Network**: k6's timing object captures detailed network phases for every HTTP request automatically.

**Lambda**: CloudWatch GetMetricStatistics API is queried periodically (every 10th iteration) to retrieve function metrics. The implementation includes retry logic and graceful failure handling for timeouts or missing permissions.

**BigQuery**: Planned implementation will leverage the BigQuery REST API. Currently includes placeholder structure ready for integration.

---

## Unified Reporting

All collected data is **consolidated into an interactive HTML report** featuring:
- Visual charts and graphs for easy interpretation
- Percentile distributions (avg, p95, p99, max)
- Clear breakdown by service
- Success/failure analysis
- Trend visualization over time

---

## Implementation Approach

The implementation follows a **phased approach**:

1. **Establish Kinesis metrics** as the baseline for load testing
2. **Integrate Lambda monitoring** for downstream visibility into the pipeline
3. **Automate collection and reporting** through GitLab CI/CD for continuous testing
4. **Expand to include BigQuery and GCP metrics** for complete end-to-end observability

---

This setup ensures a **data-driven understanding of pipeline performance**, enabling proactive optimization and faster issue resolution.
